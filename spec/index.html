The Urlcade // game authoring API

Build a cart as a plain JS object, encode it, get a URL — that URL is the game. Every link below is raw text, readable directly by a browser, a human, or an agent fetching the URL, with nothing rendered in the way.

Build a cart (for an agent)

  • skill/SKILL.md

    Start here. A short router into the reference files below — names exactly which one to load for a given task instead of making you read all of them.

  • skill/references/workflow.md

    The end-to-end recipe and a complete minimal worked example — load this first when building a new cart.

  • cart-object.md

    Every top-level field of the cart object: palette, entity types, sprites/tiles, HUD, input, camera, map generator config.

  • opcodes.md

    The full hook-bytecode instruction set, grouped, with exact stack push/pop order for every opcode.

  • hooks.md

    What each of the six lifecycle hooks runs, how often, and what self/a/b are bound to.

  • map-generators.md

    The track/cave/platform generators' config shapes and token vocabularies.

  • binary-format.md

    The exact byte layout and URL transport (compression, the name/author envelope) — for debugging a fragment that won't decode.

  • kernel.js

    The actual encodeCart/decodeCart/opcode table/ assembler/VM/compression/disassembler — one dependency-free file, the single source of truth for the cart format (the runtime and its Debug view both load this file directly, not a copy of it). Runs standalone under Node or any JS host — no browser, no network, no build step.

  • fixtures.md

    Known-good (cart description → exact bytes → exact fragment string) examples generated by kernel.js. Check your own implementation against these directly.

Learn the Urlcade (for a human)

  • learn/

    A taught tour with visuals and small live demos — the palette generator, the VM, the map generators — each one calling the real kernel.js, not a description of it.

Play it, debug it, compile it

  • The live runtime

    The shelf auto-generates a card (thumbnail, name, author) for each playable cartridge purely by decoding its own URL fragment — including carts authored entirely outside this repo, with no source checked in at all; any validly-encoded cart fragment plays at /#<fragment>, not only the ones on the shelf. From any playing game, Debug has three tabs: Assets (palette, sprites, tiles), Logic (overview, map, entities, disassembled hooks), and Source (the cart as an editable object including name/author, recompiling as you type, with its compile status — a specific error, or a "Play this version" link — right at the top) — a real authoring loop, not just a viewer. + New Cart on the shelf opens Debug on a small starter cart to edit from scratch.

Part of The Urlcade — a self-hosted game authoring API.
